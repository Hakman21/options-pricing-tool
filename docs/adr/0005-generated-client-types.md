# 5. The frontend's types are generated from the API, not written

Status: accepted · 2026-08-23

## Context

A hand-written TypeScript interface mirroring a Pydantic model is correct on the day
it is written. The failure mode is silent: someone renames a field, the interface
still compiles, and the bug surfaces as `undefined` in a browser.

## Decision

`frontend/src/types/api.d.ts` is generated by `openapi-typescript` from the
backend's OpenAPI document and committed. A CI job regenerates it and fails the
build on any diff:

```
uv run python -c "...app.openapi()..." > openapi.json
npm run generate:types
git diff --exit-code -- frontend/src/types/api.d.ts
```

`openapi.json` itself is gitignored - generated on demand, never a second source of
truth.

## Consequences

- A backend change that breaks the client is a failed build, not a runtime error.
  This is the single highest-value job in the pipeline.
- The generated file must never be hand-edited; it is in `.prettierignore` and
  eslint's ignore list to make that obvious.
- Zod schemas in `lib/schema.ts` still duplicate the validation *bounds* by hand,
  because OpenAPI constraints do not translate into zod automatically. A contract
  test asserts the two agree, so drift there surfaces too.
